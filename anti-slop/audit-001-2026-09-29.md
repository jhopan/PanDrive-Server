# PanDrive UI Audit 001

Scope: pending UI work for share controls, reservation visibility, OAuth config migration picker, and transfer dashboard.

No DESIGN.md or explicit visual direction was found. Under R-37, new UI must not ship as a visual deliverable until direction exists or approved findings are addressed. Existing product style is treated as an implementation constraint, not new direction.

1. HIGH, R-37, Design direction missing.
   Reason: New security and transfer controls need a clear visual hierarchy, especially destructive share and quota states. Without direction, additions risk becoming generic dashboard cards.
   Fix: Provide a short visual direction, or approve a functional draft with explicit ENERGY 1 / RHYTHM 1 / MOTION 1.

2. HIGH, R-26 and R-27, Share security controls need complete interaction states.
   Reason: Password and download-limit controls need disabled, saved, validation-error, and existing-link states. A bare pair of inputs would be a dead or misleading control.
   Fix: Build controls with real save action plus loading, success, validation, and disabled states.

3. HIGH, R-32, OAuth migration flow needs keyboard-safe confirmation.
   Reason: Moving an account to another OAuth config triggers real Google OAuth reconnect. A raw prompt field is error-prone and has weak keyboard/accessibility behavior.
   Fix: Replace prompt with a labelled selector and explicit confirmation dialog, Escape closes, focus remains visible.

4. MEDIUM, R-05 and R-31, Transfer information needs one operational page, not scattered cards.
   Reason: Active files, chunks, reservations, OAuth quota, split downloads, and retry state form one operational task. Separate Settings/Uploads fragments obscure what is currently consuming capacity.
   Fix: Add one /transfers page with sections ordered by current work: active transfers, capacity reservations, then OAuth quota. Purpose: incident diagnosis and transfer control.

5. MEDIUM, R-25 and R-29, State colors need restrained semantic use.
   Reason: Reservation expiry, quota pressure, failed transfer, and share cap are safety states. They need text labels and contrast-safe semantic color, not color alone or decorative badges.
   Fix: Use existing app semantic colors only with a text status and sufficient contrast in both themes.

6. LOW, R-03, Pending controls must hold on mobile.
   Reason: Reservation rows and config quota rows contain long account emails, numeric limits, expiry timestamps, and buttons. They need wrap-first rows and 44px controls rather than horizontal tables.
   Fix: Use stacked rows below the mobile breakpoint; test narrow viewport after implementation.
